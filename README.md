# Практические работы ТРПО №1–3

Три самостоятельных учебных веб-интерфейса на данных из предоставленных архивов. Откройте общую стартовую страницу и выберите работу.

## Запуск

Нужен Node.js 22 или новее. Готовые HTML, CSS и локальные файлы Bootstrap уже включены в репозиторий.

```sh
npm start
```

Альтернатива без npm: `node scripts/serve.mjs`.

Откройте http://127.0.0.1:4173. Используйте локальный сервер: загрузка JSON и JavaScript-модулей при открытии через `file://` ограничивается браузером.

Для изменения и повторной сборки:

```sh
npm ci
npm run build
npm test
```

## Данные и сборка

`scripts/build.mjs` читает CSV/JSON и генерирует страницы. Для изменений структуры страниц редактируйте шаблоны в этом файле, затем выполняйте сборку. Не редактируйте сгенерированные HTML вручную.

- №1: `content.csv` → карточки, таблица и варианты выбора; `navigation.json` → навигация. Время занятий добавлено как явно обозначенный демонстрационный пример.
- №2: `catalog.csv` → карточки; `theme.json` → `_tokens.scss` → Sass → `styles.css`. Логические файлы стилей используют `@use`, переменные, вложенность и mixin. Измените тему в JSON и пересоберите проект.
- №3: `dashboard.json` → начальные метрики и строки; `notifications.json` загружается браузером. При ошибке загрузки появляется предупреждение и используются встроенные сообщения.
- Bootstrap копируется из зафиксированной npm-зависимости при сборке. После сборки внешняя сеть для страниц не нужна.

Регистрация в №1 только демонстрирует проверку ввода. Операции в №3 изменяются в памяти страницы до перезагрузки; метрики остаются снимком исходного JSON. Серверная отправка, учётные записи и база данных не входят в эти работы.

## Основание и ограничения

В исходных архивах есть dataset и README учебных примеров, но нет полных текстов заданий. В архиве №1 присутствовал лишь служебный файл Word с префиксом `~$`, не содержащий полноценного задания. Он исключён из проекта. Реализация выполнена по темам и техническим требованиям README; соответствие неизвестным дополнительным требованиям преподавателя не заявляется.

Исходные примеры сохранены в `references/` для сравнения. Основные страницы написаны отдельно, на реальных данных из архивов.

## Подготовка GitHub

Проект подготовлен для одного репозитория, например `trpo-practices`. `.gitignore` исключает зависимости, секреты и служебные файлы; `package-lock.json` фиксирует зависимости, готовые страницы и `vendor/` включаются в Git. Перед публикацией нужно выбрать владельца, имя репозитория и видимость. Публикация не выполнена автоматически.

Для GitHub Pages можно после загрузки включить **Deploy from a branch → main → /(root)**: все пути относительные. Включение Pages — отдельное действие публикации.
